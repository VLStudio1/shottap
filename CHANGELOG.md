# Changelog

All notable changes to this project will be documented in this file.

This project follows the spirit of [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

## [0.6.4] - 2026-11-10

### Fixed

- Opening or revealing whole-computer results works again: the drive-root path guard never matched, so the Open and "Show in folder" buttons silently did nothing for results outside the library in that mode.
- Searches no longer match the query against itself: library thumbnails are excluded from results (previously every capture matched its own thumbnail at 100% once the library tree was in scope), and a dropped file excludes its own path when it lives inside the search scope.
- A superseded search can no longer tear the decode farm out from under the live search mid-run, which could silently return truncated results marked as complete.
- The persisted hash cache keeps growing across searches up to its own limit (200,000 entries) instead of being cut back to a single search's decode budget, so progressive coverage actually survives restarts.
- Cancelling a search now stops the folder walk immediately instead of churning the disk for a result nobody is waiting for.
- Library results show the capture's real file size instead of its thumbnail's; result previews are generated by the decode farm so many matches no longer block the main process; oversized (over 50 MB) query images are rejected with a clear message; a failed Browse search can no longer leave the view stuck at "Searching…"; and case-variant folder spellings no longer walk the same tree twice on Windows.

## [0.6.3] - 2026-11-09

### Changed

- Reverse Search now decodes images in parallel across hidden renderers (about 2.5x faster hashing on a typical multi-core machine), and hashes every image — queries included — through one shared resampling pipeline so comparisons stay exact.
- Folder walks stat files in small parallel batches, so scanning very large folders no longer spends seconds before the first image is compared.

## [0.6.2] - 2026-11-09

### Added

- Added a "Whole computer" toggle to Reverse Search: searches every fixed drive while skipping system folders (Windows, Program Files, AppData and friends) that only hold wallpaper and installer imagery.
- Reverse Search now compares already-indexed images for free even past the newest-5,000 decode budget, so every repeat search over a huge folder covers more ground than the last.

### Fixed

- Searching a broad folder no longer looks broken: unreadable system sub-folders are skipped silently, and only a folder you explicitly picked that cannot be read is reported.
- Dropping a non-image file onto Reverse Search now explains what to do instead of showing a terse format error.

## [0.6.1] - 2026-11-09

### Security

- Updated the bundled Electron runtime from 42.9.1 to 42.11.18, picking up upstream Chromium and Node.js security fixes (12 known advisories).
- Updated electron-builder to 26.18.1 and pinned vulnerable build-time transitive dependencies (minimatch, undici); `npm audit` now reports zero vulnerabilities. None of these ship inside the app, which keeps zero runtime dependencies.

## [0.6.0] - 2026-11-08

### Added

- Added Reverse Search: drop or browse for an image to find visual copies — exact matches and near-duplicates such as resized or re-saved files — stored on this computer.
- Reverse Search always covers the capture library and any folders you add; picked folders are remembered between sessions.
- Added a "Find similar images" action to the capture context menu.
- Added a persisted image-hash cache so repeat searches skip already-hashed files.

### Fixed

- Browsing for an image now shows the searching state and progress immediately after the file is chosen, instead of appearing to do nothing while the search ran silently.
- Tamed Reverse Search resource use: each search now compares against the newest 5,000 images (and says so when the folders hold more), decodes one image at a time so captures and the UI stay responsive, hashes library captures from their stored thumbnails instead of full files, and can be cancelled mid-search.

### Notes

- Reverse Search runs fully offline with perceptual hashing (dHash); no images leave the machine and no new dependencies were added.

## [0.5.3] - 2026-08-31

### Added

- Added line, rectangle, square, ellipse, and circle tools to the screenshot editor.
- Added deeper self-test coverage for Copy All after clearing the clipboard, after clearing the session queue, and with large screenshot sets.

### Fixed

- Made Copy All fall back to the Captures library when the current session queue is empty.
- Added a bounded composite image fallback so paste targets that ignore multi-file clipboard data still receive all copied screenshots as one image.
